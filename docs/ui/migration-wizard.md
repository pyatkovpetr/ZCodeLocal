# Мастер миграции

Окно «Мастер миграции» переносит локальную историю и настройки в ZCode. Оно открывается при первом запуске и из настроек, пункт «Миграция». Шаги идут по порядку. «Продолжить» только открывает следующий шаг. Запись сессий и файлов делают отдельные кнопки на шагах.

## 1. Импорт сессий

Читает уже существующие переписки на этом компьютере. Модель не вызывается.

| Источник | Папка |
| --- | --- |
| Claude | `~/.claude/projects/**/*.jsonl` |
| Codex | `~/.codex/sessions` и `archived_sessions`, файлы `.jsonl` и `.jsonl.zst` |
| Kimi | `~/.kimi/sessions` и `~/.kimi-code/sessions` |
| Cursor | `~/.cursor/projects/**/agent-transcripts/**/*.jsonl` и база `state.vscdb` в профиле Cursor |

Codex не читается из `state_*.sqlite`.

Полезной считается сессия, где есть задача пользователя и ответ или успешный результат инструмента. Остальные попадают в «Бесполезные» с причиной: нет задачи, нет результата, системный шум или обрыв без результата. Название берётся из имени сессии в исходном приложении, иначе из `<user_query>` или первой фразы пользователя. Служебный блок `<environment_context>` в название и в историю не пишется, поэтому открытая сессия показывает сами реплики.

Галочки меняют числа сразу:

- «Полезные (отмечено из всего)» и «Бесполезные (отмечено из всего)».
- «Импортировать выбранные (N)» — сумма отмеченных в видимых источниках.
- Снятие Claude, Codex, Kimi или Cursor убирает этот источник из списка и из числа импорта.

Отдельной кнопки импорта на этом шаге нет. «Продолжить» запускает запись отмеченных сессий в фоне и сразу открывает следующий шаг. Задачи появляются в списке «Задачи» текущего рабочего пространства по мере записи. Повторное «Продолжить» в том же мастере импорт не запускает снова. Повторный импорт той же сессии в новом открытии мастера создаёт новую задачу, старую не затирает.

## 2. Сеансы

Отдельный старый поиск рабочих пространств Claude Code: окно «последние N дней» и предел числа сеансов. Пустой список значит, что этот поиск ничего не нашёл. Сессии из шага 1 здесь не повторяются.

## 3. Навыки

Навыки из каталогов внешних агентов, например `~/.codex/skills`. Режим «Символьная ссылка» или копия, область «Глобально» или текущий проект. Пока галочки не стоят, шаг ничего не пишет.

## 4. MCP-серверы

Определения MCP из конфигов внешних агентов. «В этой области MCP-серверы не найдены» значит, что в выбранной области их нет. Это не ошибка базы.

## 5. Команды

Слэш-команды внешних агентов. Ноль команд значит, что каталоги команд пустые.

## 6. AGENTS.md

Копирует пользовательскую память Claude из `~/.claude/CLAUDE.md` в `~/.zcode/AGENTS.md`. Если исходного файла нет, шаг показывает предупреждение и ничего не копирует. Файл `CLAUDE.md` внутри отдельного проекта сюда не подставляется.

«Начать миграцию» доступна и когда навыки, команды и `CLAUDE.md` не выбраны. На этом шаге и на экране завершения написано: миграция сессий продолжится в фоне, сессии будут добавляться по мере сканирования.

## 7. Миграция

Запускает перенос того, что отмечено на шагах 2–6: сеансы Claude из шага 2, навыки, MCP, команды и `AGENTS.md`. Карточка «Миграция сеансов» считает только шаг 2. Сессии, импортированные кнопкой на шаге 1, в эту цифру не входят.

«Импорт настроек» — навыки, команды и MCP. «Начать работу с ZCode» закрывает мастер.

## Если чат показывает SQLite startup failed: startup_status_timeout

Это не повреждение базы. Окно агента ждало первый статус подготовки SQLite 30 секунд и не получило его: поток host был занят чтением тысяч сессий и не разбирал ответ агента. После такого сбоя тот же процесс агента остаётся мёртвым, и повторные вызовы сразу возвращают ту же ошибку.

Следующее открытие рабочего пространства поднимает новый процесс агента. Сканирование больше не держит поток host целиком: между сессиями управление возвращается циклу событий, чтобы статус базы успел дойти.
